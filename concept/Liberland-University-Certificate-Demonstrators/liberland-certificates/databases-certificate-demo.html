01 / The programme

Build a skill you can use.

The programme compares SQL tables and MongoDB documents through a small order-management case. It introduces safe updates, validation and basic access control; it is a foundation in database use rather than advanced database administration.

Who this is for

  • Analysts who need to retrieve their own data
  • Junior developers learning persistence
  • Learners preparing for data engineering

Before you begin

Required. Comfort with tables, identifiers and logical conditions. No prior database programming required.

Helpful. Basic scripting or spreadsheet lookup experience.

Tools & access

A local SQL practice database such as SQLite and a MongoDB practice environment with a query shell. Use disposable sample data.

Study hours include explanation, guided practice, independent activities and assessment. Software setup may require additional time. Actual delivery dates, support and fees are not set in this demonstrator.

02 / Learning outcomes

What you will be able to do.

  1. Design tables with keys and sensible relationships
  2. Retrieve and aggregate records using SQL
  3. Explain how joins affect row counts
  4. Model and query simple MongoDB documents
  5. Choose embedding or references for a stated use case
  6. Apply basic validation, safe-change and access principles
03 / Programme structure

6 modules. 24 purposeful hours.

Open a module to explore its topics and practical activity. Hours are the total learning allocation, not video duration.

01Data models & integrity3 hours
Topics

Entities; keys; one-to-many relationships; constraints; normalisation basics.

Practical activity

Model customers, orders and order lines with explicit keys.

02SQL queries5 hours
Topics

SELECT; WHERE; ORDER BY; NULL; GROUP BY; aggregate functions.

Practical activity

Answer five order questions and check the treatment of missing values.

03Joins & safe changes4 hours
Topics

INNER and LEFT joins; duplication; INSERT and UPDATE; transaction concepts.

Practical activity

Join orders to lines, reconcile totals and rehearse a change in a practice database.

04MongoDB documents4 hours
Topics

Collections; document shape; nested fields; find; projections; updates.

Practical activity

Represent an order as a document and query its nested delivery details.

05Aggregation & design choices3 hours
Topics

Aggregation pipelines; embedding versus references; index concepts; validation and access.

Practical activity

Aggregate document orders and justify one modelling decision.

06Dual-model project5 hours
Topics

Equivalent queries; integrity checks; documentation; assessment.

Practical activity

Deliver relational and document versions of the order case with query results.

Total: 24 hours · Final project and assessment are included in the final module.

04 / Apply your learning
The final project

Order-system comparison: answer the same business questions from tables and documents.

Your submission

  • A relational schema with sample records and five checked SQL queries
  • Equivalent MongoDB documents and two aggregation/query examples
  • A design note covering keys, duplication, safe changes and access

Assessment & feedback

Proposed assessment: module practice portfolio 40%; final project 60%. Formative lesson checks allow retries and do not contribute to the award score.

Final-project marking criteria

  • Query accuracy and validation — 40%
  • Data modelling and integrity — 35%
  • Design rationale and documentation — 25%

A tutor would review the submitted work against these criteria. The browser check below assesses only the sample question.

05 / Completion

How the certificate would be earned.

A proposed Liberland University certificate of completion would record the programme title and 24 study hours after the requirements are met. This demo makes no claim of academic credit or external accreditation.

  • Complete all modules and submit the practice portfolio and final project.
  • Achieve at least 60% overall and at least 60% on the final project.
  • Meet the programme’s essential checks listed below and acknowledge any external help.
  • Revise work after feedback if needed; proposed resubmission arrangements require academic approval.

Essential programme check: Keys and joins must preserve the intended grain; submitted results must match source records.
